================================================================================
          ANÁLISIS DETALLADO: COMPONENTES Y CONFIGURACIÓN DEL SISTEMA
================================================================================

Este documento profundiza en tres pilares fundamentales del proyecto: la lógica
de los componentes, la configuración de dependencias y la gestión de módulos.

--------------------------------------------------------------------------------
1. ANÁLISIS PROFUNDO DE COMPONENTES (src/components/)
--------------------------------------------------------------------------------
En este proyecto, los componentes son funciones puras de JavaScript que reciben
datos y devuelven una cadena de texto HTML. Esto permite que la interfaz sea
dinámica y eficiente.

A. taskCard.js (La Tarjeta de Tarea)
Es la unidad visual más pequeña del tablero. Su complejidad radica en:
- Renderizado Condicional: El componente no solo muestra el título, sino que
  cambia su apariencia según el estado. Si la tarea está en 'done', aplica
  estilos de opacidad y tachado al texto.
- Seguridad XSS (Cross-Site Scripting): Implementa una función `escapeHtml()`.
  Esto es crítico porque evita que un usuario malintencionado escriba código
  JavaScript en el título de una tarea que luego se ejecute en el navegador de
  otro usuario.
- Lógica de Permisos: Antes de dibujar el botón de "Editar", el componente
  verifica si el usuario actual es Administrador o el dueño de la tarea. Si no
  cumple ninguna de las dos, el botón simplemente no se renderiza en el HTML.

B. taskModal.js (El Formulario de Gestión)
Es la interfaz de entrada de datos. Su funcionamiento destaca por:
- Control de Atributos Dinámicos: Dependiendo del rol del usuario, el componente
  asigna el atributo `readonly` a ciertos campos. Un Coder puede ver el título
  de la tarea, pero el sistema bloquea el input para que no pueda modificarlo.
- Gestión de Estados: El modal maneja la transición entre los modos "Crear" y
  "Editar", cambiando los textos de los botones y los métodos de la API que
  deben invocarse (POST para crear, PATCH para actualizar).

--------------------------------------------------------------------------------
2. EL ROL DEL ARCHIVO package.json
--------------------------------------------------------------------------------
El `package.json` es el manifiesto del proyecto. No contiene código ejecutable,
sino la configuración necesaria para que el entorno de desarrollo funcione.

- Definición de Scripts: En la sección `"scripts"`, el programador definió
  atajos como `"start": "json-server --watch db.json --port 3000"`. Esto permite
  que cualquier desarrollador inicie el servidor de datos sin necesidad de
  conocer los parámetros exactos del comando de consola.
- Gestión de Dependencias: En `"devDependencies"`, se especifica la herramienta
  `json-server` y su versión. Esto garantiza la "reproducibilidad": cualquier
  persona que instale el proyecto tendrá exactamente la misma versión de la
  herramienta, evitando errores por incompatibilidad de versiones.
- Metadatos del Proyecto: Almacena el nombre, versión y descripción, facilitando
  la organización si el proyecto llegara a distribuirse como un paquete.

--------------------------------------------------------------------------------
3. ENTENDIENDO LA CARPETA node_modules
--------------------------------------------------------------------------------
`node_modules` es la carpeta donde residen físicamente todas las librerías externas
que el proyecto necesita para operar.

- El Concepto de Árbol de Dependencias: Cuando instalamos una sola herramienta
  (como `json-server`), esta a su vez depende de otras librerías más pequeñas,
  y esas de otras más. Esto crea un "árbol" de dependencias. Por eso la carpeta
  contiene cientos de directorios aunque nosotros solo hayamos instalado una
  única herramienta principal.
- Flujo de Instalación: La carpeta no se crea manualmente. Se genera al ejecutar
  `npm install`, comando que lee el `package.json`, descarga las librerías del
  registro oficial de NPM y las organiza en este directorio.
- Exclusión en Git: Debido a su tamaño masivo y a que es regenerable, nunca
  se sube al repositorio. Solo se sube el `package.json`, ya que es la "receta"
  suficiente para que cualquier otro programador reconstruya la carpeta
  `node_modules` en su propia máquina.
